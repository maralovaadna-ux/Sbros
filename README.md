## Как запустить

### 1. Создать проект в Supabase

1. Зайти на https://supabase.com → New Project
2. Дождаться создания (2-3 минуты)
3. **Включить вход по телефону (SMS OTP):** Authentication → Providers → Phone → включить.
   Понадобится SMS-провайдер (Twilio / Vonage / MessageBird) — привязать по инструкции Supabase на этой же странице. Указать API-ключи провайдера.
4. Зайти в SQL Editor → вставить содержимое `supabase/migrations/0001_init.sql` → Run.
5. (опционально, для теста) вставить содержимое `supabase/migrations/0002_seed.sql` → Run — создаст 4 демо-предложения.
6. Project Settings → API → скопировать `Project URL` и `anon public` ключ.

### 2. Настроить переменные окружения

```
cp .env.local.example .env.local
```

Вставить в `.env.local`:
```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=xxxxx
```

### 3. Установить зависимости и запустить

```bash
npm install
npm run dev
```

Открыть http://localhost:3000 — увидите экран входа по телефону.

Для продакшена — задеплоить на **Vercel**: подключить репозиторий, вставить те же 2 переменные окружения в Vercel → Settings → Environment Variables, Deploy.

### 4. Создать первого администратора

1. Зарегистрироваться в приложении обычным способом (свой номер телефона, пройти onboarding с адресом).
2. В Supabase → Table Editor → `profiles` → найти свою строку по имени → изменить поле `role` с `user` на `admin`.
3. Обновить страницу приложения — в профиле появится кнопка «⚙️ Admin-панель».

### 5. Добавить первое предложение

1. Профиль → Admin-панель → «+ Новое»
2. Заполнить название, цены, дату окончания, выбрать географию (дом/ЖК/район/город/Казахстан)
3. Добавить хотя бы один уровень цены (например: от 1 чел. — 35000 ₸, от 50 чел. — 29900 ₸)
4. Сохранить — предложение сразу появится в ленте у пользователей нужной территории.

### 6. Как протестировать механику

**Регистрация:** зайти с двух разных телефонов (или два браузера в режиме инкогнито) — задать разные адреса (один в доме/ЖК из тестового предложения, другой — в другом городе).

**Видимость по гео:** пользователь из другого города НЕ должен видеть предложение уровня "дом"/«ЖК», но должен видеть предложения уровня "city" своего города и "country".

**Участие и счётчик:** нажать «Участвовать» на одном устройстве — открыть то же предложение на втором устройстве (или просто обновить страницу) — счётчик должен обновиться сам, без перезагрузки (realtime подписка).

**Цена по уровням:** участвовать несколькими тестовыми аккаунтами подряд, наблюдая, что цена меняется при достижении порога (например, 10-й участник должен увидеть цену следующего уровня).

**Чат:** написать сообщение с одного аккаунта — на втором открытом окне с тем же предложением сообщение должно появиться само.

**Защита телефона:** в Supabase → Table Editor → `profiles` — убедиться, что колонки `phone` там нет вообще (телефон живёт только в `auth.users`, к которой у клиента нет прямого доступа).

**Admin:** заблокировать пользователя в /admin/users → с его аккаунта попробовать нажать «Участвовать» — должна быть ошибка (RLS отклонит запись).

## Известные ограничения MVP (сделано намеренно просто)

- Загрузка фото — через вставку прямой ссылки на изображение (URL), а не через upload-виджет. Storage bucket уже настроен в миграции — при желании легко подключить upload позже.
- SMS OTP требует подключения стороннего SMS-провайдера в Supabase (Twilio и т.п.) — без него вход по телефону не заработает технически, это ограничение самого Supabase, не приложения.
- Нет пагинации ленты — при 50-100 пользователях и десятке предложений это не проблема.
- Название улицы/дома при scope="building" не нормализовано (регистр, пробелы) — для точного совпадения адресов на MVP это осознанно оставлено на ручной контроль администратора при создании предложений.
